# Investigation

A read-only question. The deliverable is a cited answer, not a change.

1. **State the question you are actually answering.** If the ask is ambiguous,
   write down the reading you chose and why. Do not widen it.
2. **Find the ground truth in the repository.** Read the code, the history, the
   tests. For anything wide, send a `scout` child so the bulk stays out of this
   context window.
3. **Answer from what you read.** Every claim names the file and line it came
   from. A claim you cannot cite is a guess, and must be labelled as one.
4. **Check the answer against a second source.** Run the code, read the test, or
   check the git history. An answer that only comes from reading one file has
   not been corroborated.
5. **Say what you did not establish.** Name the parts you could not verify and
   what it would take to settle them.

Do not fix anything you find on the way. Note it and let the user decide.

The reply gives the answer first, then the evidence, then the open questions.
